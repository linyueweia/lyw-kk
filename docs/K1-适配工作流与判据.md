# KICKPI K1 板级适配：工作流与判据（官方同步版）

> 目的：让"板级 DTS / 内核配置 / 扩展脚本"的每一次改动都**有官方依据、可复核、可回滚**，
> 并且最终产物能被机器逐项断言，而不是靠人眼判断。
> 本文是本仓库板级适配工作的唯一方法学出处；与它冲突的做法一律以本文为准。

---

## 1. 证据分级（谁说了算）

同一属性出现不同取值时，按下表取舍，**低级别不能覆盖高级别**：

| 级别 | 证据 | 本机路径 | 用途 |
|---|---|---|---|
| L1 **实机运行 DT**（本板硬件真相） | 厂商 5.10 系统 `/proc/device-tree`、`/sys`、`dmesg` | `/work/kk/kickpi-k1a-live.dts`（反编译）、`/proc/device-tree` | 引脚号、GPIO 位、延时、已使能状态、外设是否在板 |
| L2 **官方 6.1 SDK 源码**（本仓库要对齐的代际） | Rockchip/KICKPI 官方仓库 | `/work/tmp/sdk-git` → `git --git-dir=... show HEAD:kernel-6.1/arch/arm64/boot/dts/rockchip/rk3568-kickpi-*.dts*` | 目标内核代际的写法、符号名、节点结构 |
| L3 **官方 5.10 镜像 DTB**（出厂固件） | RKFW 挖出的 16 个 DTB | `/work/official-dts/cand_00_175480.dtb` → `/work/tmp/offdts/*.dts` | 交叉验证 L1（同一属性两处一致才算板级定论） |
| L4 **板卡规格书** | 厂商 PDF | `/work/incoming/KICKPI-K1_Specification.pdf` → `/work/tmp/spec.txt` | 接口/容量/LED/按键等**不进 DTS**的事实 |
| L5 社区仓库（j3ffs/Kickpi-K1 等） | 仅参考 | — | **不得作为判据**（已证明源自别的板改名） |

**三线一致**（L1 = L2 = L3）→ 直接落地；
**L1 与 L2 不一致** → 先判断是"板型差异"还是"代际差异"，在改动里写中文注释说明取舍，并在报告中列出三方取值。

## 2. 工作流（五步，顺序不可跳）

```
① 取证   实机 /proc/device-tree + 官方6.1 SDK + 官方5.10 DTB 三方逐属性抄表
② 检测   脚本化差异扫描（node+property 级，带 phandle→路径解析）→ gap 清单
③ 修复   只改"有官方依据"的项；每条改动先 dry-run 打印 OLD/NEW 抽查
④ 门禁   dtc 0 ERROR → 仓库门禁 k1-gate-check.py → 产物断言（对 .dtb 而非源码）
⑤ 交付   JSON 报告（before/after + 依据 + 行号）；交付前重新 grep 行号
```

### 2.1 差异检测的三条硬规则（踩过的坑）

1. **只有"引用型属性"才按 phandle 解析**（gpios/supply/handle/remote-endpoint/pinctrl-*/…）；
   `ddr*-params`、`reg`、`interrupts` 里的裸数字是**数值**，绝不能当 phandle 改写。
2. **判断引用位时只认语义位**：`clocks/assigned-clocks/resets/phys` 是 (phandle,idx) 成对，
   只有偶数位是引用；`snps,reset-gpio` 只有第 0 位是引用（1=引脚号、2=flags，`0x1b`/`0x01`
   同时恰好是实机 phandle 号，**极易被误改**）。
3. **同一属性只能由 L1 定值**：脚本输出的 OLD/NEW 必须能被人工一眼对上实机原值。

### 2.2 修复的三条硬规则

1. 裸数值 phandle → 一律改成 `&{/绝对路径}`，且**路径必须存在于 6.1 树**（由 dtc 0 ERROR 兜底）。
2. 5.10→6.1 节点改名必须跟随：`gpioN@X → gpio@X`、`sdhci@X / dwmmc@X → mmc@X`、
   `drm-logo@00000000 → drm-logo@0`；`aliases` 必须同步（否则 dtc 报 `alias_paths`）。
3. 每次改动前自动留 `.bak-<时间>`；**单写者**：改共享文件前先查 mtime 是否刚被别人改过。

### 2.3 三重门禁（全部针对**产物**，不看源码自嗨）

| 门禁 | 命令 | 通过标准 |
|---|---|---|
| 编译 | `bash /work/tmp/verify_final.sh` | `cpp` 0 stderr，`dtc` **ERROR=0 FATAL=0**；我方文件贡献的告警逐条可解释 |
| 仓库门禁 | `python3 /work/scripts/k1-gate-check.py` | `ALL PASS` |
| 产物断言 | `python3 /work/tmp/assert_k1_dtb2.py` | `fail=0`（49 项：身份/aliases 全解析/gmac 四值与复位/LED 与按键引脚/uart+fiq/摄像头 graph 双向/SDIO pwrseq/io-domains/音频 dai/pinctrl-names/display 引用…） |

基线（2026-10-08 18:49）→ 当前：dtc WARNING **50 → 25**，`alias_paths` **4 → 0**，
`graph_endpoint` **4 → 0**，裸数值 phandle **21 → 0**，`fix.dtb` md5 `5b1245f76f9f2651d5be86578ac0768f`。

## 3. 判据速查（改到哪一项就按哪一行判）

- **网口**：`phy-mode=rgmii`、`clock_in_out=output`、gmac0 `tx/rx=0x21/0x3c`、gmac1 `0x2f/0x39`、
  `snps,reset-gpio` = gpio2 RK_PD3 / gpio3 RK_PA7 + `snps,reset-active-low` + `<0 20000 100000>`、
  `assigned-clocks/parents/rates`（rates 必含 125MHz）、`mdio/phy@0 ieee802.3-c22 reg 0`、
  pinctrl `gmac0_*` / `gmac1m1_*`、aliases `ethernet0=fe2a0000 / ethernet1=fe010000`。
- **显示**：`display-subsystem` 的 `memory-region`、7 条 `route/*connect`、`vop@fe040000` 的
  `ports/port@N/endpoint`、`hdmi@fe0a0000` 与 `hdmi-sound` 的 sound-dai 必须互相指得到。
- **存储**：`sata@fc000000/fc400000/fc800000` 与 `combphy0_us`、`pcie2x1`/`pcie3x2` 复位脚与
  regulator（vcc3v3_pcie / pcie3-regulator / minipcie-regulator / gpio-regulator / dc-12v）。
- **WiFi**：`mmc@fe000000` okay + `mmc-pwrseq = &sdio-pwrseq`、pwrseq clock（rk809 ext_clock）、
  `WIFI,poweren_gpio/host_wake_irq`、BT 走 uart8 + rts/power/wake 脚。
- **身份**：`model = "Rockchip RK3568 KICKPI K1 Board"`，
  `compatible = "rockchip,rk3568-kickpi-k1", "kickpi,k1", "rockchip,rk3568"`（L2 官方 6.1；L1 为 K1A/-k1a）。

## 4. 刻意不抄的三项（抄了会出事）

1. **`/chosen` 的 `root=PARTUUID=…`**：厂商值是 eMMC 的，kk 镜像 root 由 extlinux 提供
   → 抄过来会复现"PARTUUID 黑屏"事故。
2. **`/reserved-memory/ramoops@110000`**：厂商保留区，必须先核对本镜像 CMA/低内存占用再加。
3. **`local-mac-address`**：U-Boot 每次开机从厂商存储写入，写死会毁掉每台机器的 MAC。

## 5. 并发与只读铁律

- **硬件动作（冷启动/插拔卡/刷卡上机）一律等用户**；agent 不得自行触发。
- **不写 TF 卡、不 commit/push、不触发 CI**，直到实机冷启动验证通过。
- 子代理**只读**：只能在自己的 `/work/tmp/leg-*/` 写文件；仓库只有主线单写者。
- **行号以交付前重新 grep 为准**（源文件会被主线更新，禁止沿用早前记的行号）。
- 断言脚本本身也要有依据：期望值必须能指回 L1/L2/L3，不能凭印象写。
