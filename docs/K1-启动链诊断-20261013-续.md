## 三、根因收敛与重写（2026-10-13 下午，commit b58126a）

方法论（用户两次纠偏定调）：
1. **官方思路优先，仅板级差异才改**（lyw-OS = 明显成功案例，其 DTS 是 919 行最小覆盖模式：
   `#include "rk3568.dtsi"` 官方打底 + 板级差异，每段带实测注释）；
2. **飞牛线（lyw-kf）是本板实机验证过的板级真相**，数值直接取用。

结论：**kk 旧 DTS 是厂商 5.10 DTS 的 85KB 全量转写**（整棵 SoC 树展开覆盖在 6.1 dtsi 之上，
带入厂商 reserved/fiq/wlan·bluetooth-platdata 等 6.1 无用/有害节点）——内核极早期静默死亡的头号嫌疑。

已推送 `b58126a`：按官方模式全量重写（85KB → 19.5KB），要点：
- 补回旧转写缺失的 `chosen stdout-path = "serial2:1500000n8"`；`&uart2 okay`；**无** fiq-debugger
- gmac `phy-mode="rgmii"` + 实机 delay（gmac0: 0x21/0x3c、gmac1: 0x2f/0x39）+ reset gpio3 PB3/PA7 MAC 单持有
- mdio 占位 `ethernet-phy@1`（坑⑤ GMAC4 MDC，Maxio 必需）；PHY 节点 c22
- 工作灯 gpio0 PD5 heartbeat、风扇 gpio0 PD6 恒转；WiFi pwrseq PD5+ACTIVE_LOW+**1000ms**（R1-R5 定论）
- vdd_cpu fan53555@0x1c（厂商原厂；T68M 同位是 tcs4525）；USB 供电 PA6/PA5；io-domains 与实机一致
- 保留 kk 已验证段：NPU（rknpu/bus_npu）；eMMC/SD/NVMe(pcie3x2 x2, reset PD6)/SATA2/HDMI/USB3 父节点
- 自检：花括号平衡、66 个 &标签全部为 6.1 vendor dtsi 标准标签（旧转写覆盖段亦在用同批标签）
