## 一、现象（以用户最终修正为准）

- 实机刷过一次 **lyw-kk 最新成功构建的镜像**（run `37867285663` / commit `53a57bc3`，
  产物 `iNextOSA_26.2.1_Kickpi-k1_trixie_vendor_6.1.115.img` 5,108,662,272 B）
- **u-boot 全程有输出**，最后一行 `Starting kernel ...`
- **之后串口完全静默**——**没有** `Waiting for root device`（用户最初贴的那行是记错，已修正）
- **系统灯不闪、网口灯不亮** → 内核没有真正运行（heartbeat 与 loglevel 无关）
- TF 卡 = 16G（容量排除）
- 手段提示：armbianEnv `verbosity=1` → cmdline `loglevel=1` → **内核正常消息本来也会被全静音**；
  但 initramfs 的 `Waiting` echo 不受 loglevel 管，它没出现 = initramfs 没执行到那步

## 三、头号嫌疑（待 28f0ede 实测裁决）

**DDR 固件 `rk3568_ddr_1560MHz_v1.21.bin`（框架默认）在 K1 上半残**：
- u-boot 只碰少量内存 → 撑得住（`Starting kernel` 能打印）
- 内核一开 MMU 全 4GB 大范围访问 → 训练差的内存总线出错 → **早死**（静默 + 灯全灭）
- 同族证据：T68M 上 v1.21 训练**直接失败**（lyw-OS README 证据链）；K1 飞牛线 1560 系列 v1.26 **SPL 即断**
- **K1 真机 eMMC 原厂 = `ddr-v1.23-03ea844c5d` = rkbin `rk3568_ddr_1056MHz_v1.23.bin`**
  （本机实测提取；文件内**不含任何频率串**，判据只能用指纹 03ea844c5d）

### 已推送的修复（commit `28f0ede`，CI 构建中）
- `build.yml`：构建前 sed 替换 `1560_v1.21 → 1056_v1.23`（照抄 lyw-OS）+ 替换后断言
- `tools/verify-image.sh (0)`：断言方向反转——必须命中 `03ea844c5d`，拒绝 `f366f69a7d`(T68M V1.18) 与 `v1.21`
- README DDR 章节改写为证据链版本
